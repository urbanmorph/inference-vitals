# AGENTS.md: helping someone use inference-vitals

For coding agents (Claude Code, Codex, Cursor, Copilot and others) helping a user. inference-vitals is
a local dashboard for running and fine-tuning AI models on an Apple Silicon Mac or Linux with NVIDIA
GPUs. Everything runs on the user's machine on `127.0.0.1`. Details are in [docs/](docs/); this page is
the short, task-shaped version. To change inference-vitals itself, read [CONTRIBUTING.md](CONTRIBUTING.md).

## Set it up

```sh
brew install uv prometheus macmon          # Mac. Linux: uv, prometheus, and the NVIDIA driver
git clone https://github.com/urbanmorph/inference-vitals.git && cd inference-vitals
uv run inference-vitals start              # starts four services, each only if not running
```

Then the page is at `http://127.0.0.1:3000`. `uv run inference-vitals status` must show every service
answering; if one says NOT READY, its log path is printed: read it (a port in use is the usual cause).

## What the user wants → what to do

| The user wants to watch… | Do this | They change |
| --- | --- | --- |
| Ollama, LM Studio, llama.cpp, an MLX server, any OpenAI-style engine | `uv run inference-vitals proxy --to http://127.0.0.1:<engine port>` (Ollama 11434, LM Studio 1234, llama.cpp 8080) | Their app's base URL to `http://127.0.0.1:8401` |
| Their own Python inference loop | Add `inference_vitals.metrics.Metrics` and `serve(live, 8400)`: [docs/connect.md](docs/connect.md#your-own-python-code-the-library) | Three calls in the loop |
| An mlx-vlm or mlx-lm fine-tune | `uv run inference-vitals train --name <run> -- <their training command>` | Nothing |
| A fine-tune already writing a log | `uv run inference-vitals watch-training <log> --name <run>` | Nothing |
| A fine-tune in another framework | Add `inference_vitals.training`: [docs/training.md](docs/training.md#3-report-from-your-own-training-loop) | A few calls in the loop |
| Only the machine (memory, heat, power, battery) | Nothing more after `start` | Nothing |

Only one of the proxy, the library, `train` and `watch-training` can report at a time: they share port
8400.

## Check it works

- `curl -s 127.0.0.1:8400/metrics | head` shows `vllm:` or `vitals_` lines while something reports.
- The page's band names the model (Running) or the run (Training).
- `uv run inference-vitals status` lists every service as answering.

## Symptoms

| Symptom | Cause | Fix |
| --- | --- | --- |
| Band says "Nothing reporting" | Nothing on 8400 | Start the proxy, the library, or `train`; check `curl 127.0.0.1:8400/metrics` |
| `NOT READY` from `start` | Port in use, often a `brew services` copy | `brew services stop prometheus` (or the named one), then `start` |
| Tiles empty with the proxy: Progress, Context used (and GPU mem left shows the whole machine) | A proxy cannot see these | Expected; the library reports them |
| A fine-tune shows no numbers | Its trainer's output format is not known | Use `inference_vitals.training` in the loop, or add the format ([CONTRIBUTING.md](CONTRIBUTING.md)) |
| `address already in use` on 8400 | Two reporters at once | Stop one |
| Machine tiles empty on Linux | No `nvidia-smi`, or no CPU sensor (VMs) | Install the NVIDIA driver; CPU temperature needs real hardware |

## Rules

- Keep everything on `127.0.0.1`. Do not expose the ports to a network.
- Numbers only: never send prompts, answers, file names or ids as metric labels. Run names and model
  names are labels, so keep them non-private.
- Do not edit the dashboard in Grafana; it is generated by `monitor.py` and `ui.py`.
- Every metric name is in [docs/metrics.md](docs/metrics.md).
